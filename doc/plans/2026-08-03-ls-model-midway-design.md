# ls-model-midway 透传服务设计

## 目标

在 `ls-model-midway` 中实现一个部署于境外的 Node.js HTTP 中继，使国内的
`ls-model-api` 能够访问固定的云雾 API 上游。中继只负责 HTTP 传输，不解析、
校验、记录、缓存或改写模型调用参数与响应内容。

## 方案

使用 Node.js 原生 `http` 和 `https` 模块实现流式管道转发，不引入 Web 框架或
代理依赖。服务通过 `UPSTREAM_BASE_URL` 配置唯一上游，通过 `PORT` 配置监听
端口。

每个入站请求按以下方式转发：

- 保留 HTTP 方法、路径和查询字符串。
- 保留端到端请求头；移除 HTTP 规范要求不得转发的逐跳头，并为固定上游重建
  `Host`。
- 不读取或反序列化请求体，直接将入站流写入上游请求。
- 保留上游状态码和端到端响应头。
- 不读取或反序列化响应体，直接将上游响应流写回调用方，以兼容 JSON、SSE、
  图片、视频及其他二进制内容。

## 边界与错误处理

- 服务不提供鉴权；访问控制由部署环境的网络白名单负责。
- 服务不是通用开放代理，调用方不能指定目标主机。
- 服务不记录请求头、请求体或响应体，避免泄露模型密钥和内容。
- 上游连接或传输在响应开始前失败时返回 `502 Bad Gateway`。
- 客户端提前断开时终止对应的上游请求。
- 不设置业务级超时、请求体大小限制、重试、限流、缓存或参数校验。

## 验证

使用 Node.js 内置测试运行器启动本地假上游和中继，验证：

1. 方法、路径、查询参数、请求头和原始请求体被正确转发。
2. 上游状态码、响应头及二进制响应体被正确返回。
3. 响应分块可在上游结束前到达调用方，证明没有缓冲整个响应。
4. 上游无法连接时中继返回 502。
5. 调用方不能通过请求内容改变固定上游目标。
